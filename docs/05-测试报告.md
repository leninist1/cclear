## 二、发现 Bug 汇总

### BUG-1（中等）- `normalize_path` 对根路径处理不当

**位置：** `services.py:44-47`  
**现象：** `normalize_path("C:\\")` 返回 `"c:"` 而非 `"c:\\"`

```python
def normalize_path(target_path: str) -> str:
    normalized = os.path.abspath(target_path)
    normalized = os.path.normpath(normalized)
    return os.path.normcase(normalized.rstrip("\\/"))
```

`rstrip("\\/")` 将末尾的分隔符去掉，对于根路径 `C:\` 会被处理为 `C:`，而 `C:` 在 Windows 中表示"当前驱动器 C 的当前目录"，与 `C:\`（根目录）含义不同。

**影响范围：**
- 当用户扫描盘符根目录（如 `C:\`）时，缓存键生成会基于 `"c:"` 而非 `"c:\\"`
- `is_path_inside` 对根路径的判断间接正确（因为 startswith 检查恰好通过），但语义不严谨
- 缓存路径 `get_snapshot_path("C:\\")` 和 `get_snapshot_path("C:\\Users")` 会映射到不同的 hash，导致根路径扫描的缓存无法被子路径搜索复用

**建议修复：**
```python
def normalize_path(target_path: str) -> str:
    normalized = os.path.abspath(target_path)
    normalized = os.path.normpath(normalized)
    result = os.path.normcase(normalized.rstrip("\\/"))
    # 保留根路径分隔符：如 C:\ 不应变为 C:
    if len(result) == 2 and result[1] == ':':
        result += os.sep
    return result
```

### BUG-2（低）- `_collect_old_entries` 将目录作为清理目标但 size 仅为目录入口大小

**位置：** `services.py:582-598`  
**现象：** 当扫描临时目录时，旧目录本身也会被加入 `targets` 列表，但其 `size` 字段仅为目录元数据大小（通常为 0），不包含目录内文件的总大小。

**实际测试结果：**
```
count: 3
size: 3000
   old.txt 1000
   subdir 0        ← BUG: 目录实际包含 2000 字节内容，但报告为 0
   deep_old.txt 2000
```

**影响范围：**
- `analyze_cleanup` 返回的 `estimated_recoverable_bytes` 低估了可回收空间
- 用户在 UI 上看到的目录大小为 0，可能误导用户认为该目录为空
- `run_temp_cleanup` 中 `reclaimed_bytes` 统计也会低估

**建议修复：** 如果要将目录作为清理目标，应递归计算目录总大小；或者不在 targets 中包含目录，只包含文件。

### BUG-3（低）- `extension_label` 对 dotfile（如 `.gitignore`）返回"(无扩展名)"

**位置：** `services.py:88-90`  
**现象：** `extension_label(".gitignore")` 返回 `"(无扩展名)"`

```python
def extension_label(file_path: str) -> str:
    extension = pathlib.Path(file_path).suffix.lower()
    return extension or "(无扩展名)"
```

Python 的 `pathlib.Path(".gitignore").suffix` 返回空字符串，导致 `.gitignore`、`.env`、`.htaccess` 等 dotfile 都被归入"(无扩展名)"类别。

**影响范围：**
- 扫描结果中 `.gitignore` 等文件不会按真实"扩展名"分类
- 用户可能困惑为什么这么多文件没有"扩展名"

**建议修复：** 对 dotfile 使用 `pathlib.Path(file_path).name` 作为分类依据，或者特判以点开头的文件名。

---

### BUG-4（低）- `format_bytes` 无法处理负数值

**位置：** `app.py:21-35`  
**现象：** `format_bytes(-1)` 返回 `"-1 B"`，这是无意义的显示值

**影响范围：** 虽然正常场景下文件大小不会为负数，但缺少防御性校验。在异常数据场景（如 stat 返回错误值）下可能显示异常。

**建议修复：** 增加负数检查，将负数显示为 `"0 B"` 或 `"N/A"`。

---

### BUG-5（低）- `search_files` 接受负数的 `min_size_bytes` 参数

**位置：** `services.py:414-552`, `app.py:442`  
**现象：** 当用户在搜索 UI 输入负数的最小大小时，`search_files` 会接受负值且匹配所有文件，因为 `item["size"] < min_size_bytes` 中负数比任何文件大小都小。

**影响范围：** UI 层 `app.py:442` 将输入转为浮点数后直接乘以 1024*1024，未校验正负。负数输入会导致最小大小过滤器被绕过。

**建议修复：** 在 `app.py` 中将 `min_size_bytes` 限制为 >= 0，或在 `search_files` 入口校验参数。

---

### BUG-6（低）- 下载目录路径硬编码

**位置：** `services.py:665`  
**现象：** 下载目录固定为 `pathlib.Path.home() / "Downloads"`，如果用户已将下载文件夹移到其他位置（如 D 盘），则无法正确分析。

**影响范围：** 在 Windows 上，用户可能通过系统设置将下载文件夹重定向到其他驱动器，此时分析结果不准确。

**建议修复：** 使用 Windows API 或注册表读取实际下载文件夹路径。

---

### BUG-7（低）- `save_snapshot` 非原子写入

**位置：** `cache_store.py:60-67`  
**现象：** `save_snapshot` 直接使用 `write_text` 写入文件，如果在写入过程中进程崩溃或断电，缓存文件可能损坏（内容不完整）。

**影响范围：** 虽然损坏的缓存文件在 `load_snapshot` 中会被捕获并返回 `None`（不会崩溃），但重新扫描会消耗更多时间。

**建议修复：** 先写入临时文件，再原子性地重命名为目标文件名。
