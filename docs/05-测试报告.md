## 三、回归 Bug

### NEW-BUG-1（中等）- `is_path_inside` 对根路径判断回归

**位置：** `services.py:60-70`  
**原因：** BUG-1 的修复使 `normalize_path("C:\\")` 返回 `"c:\\"` 而非旧版的 `"c:"`，但 `is_path_inside` 使用 `target.startswith(parent + os.sep)` 进行前缀匹配。当 `parent` 为根路径 `"c:\\"` 时，`parent + os.sep` 变为 `"c:\\\\"` ，导致子路径匹配失败。

**复现场景：**
```python
is_path_inside("C:\\Users", "C:\\")    # 返回 False（应为 True）
is_path_inside("C:\\Windows", "C:\\")   # 返回 False（应为 True）
```

**当前影响范围：**
- `is_path_inside` 不直接以盘符根路径作为 `parent` 参数被核心业务逻辑调用
- `get_protected_paths()` 返回的是 `C:\Windows` 等非根路径，受保护路径检测功能**不受影响**
- `build_risk_level` 中的 `is_path_inside(target, temp_path)` 和 `is_path_inside(target, downloads_path)` 的参数均非根路径，**不受影响**
- 缓存键 `_cache_key` 使用 `normalize_path` 的结果做 hash，与 `is_path_inside` 无关，缓存功能**不受影响**
- 如果未来有代码以盘符根路径作为 `parent` 调用 `is_path_inside`，则会出错

**建议修复：**
```python
def is_path_inside(target_path: str, parent_path: str) -> bool:
    target = normalize_path(target_path)
    parent = normalize_path(parent_path)
    if target == parent:
        return True
    parent_prefix = parent.rstrip("\\/") + os.sep
    return target.startswith(parent_prefix)
```

### NEW-BUG-2（低）- `_collect_old_entries` 目录大小包含新旧全部文件

**位置：** `services.py:655-673`  
**原因：** BUG-2 的修复使用 `_measure_directory_size` 递归计算目录总大小，但该函数计算目录内的**所有文件**（既包含旧文件也包含新文件），导致可回收空间估算偏高。

**复现场景：**
- 旧目录 `sub/` 包含一个 5KB 旧文件和一个 10KB 新文件
- `_collect_old_entries` 报告 `sub/` 可回收大小为 15KB
- 实际用户仅应清理 5KB 旧文件

**影响范围：**
- `analyze_cleanup` 返回的 `estimated_recoverable_bytes` 可能高估可回收空间
- UI 显示的目录大小可能误导用户

**建议修复：** `_measure_directory_size` 增加截止时间参数，仅计算旧文件大小；或者在 targets 中标注目录为"混合新旧"风险等级。
