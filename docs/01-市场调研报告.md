# 磁盘管理工具市场调研报告

## 1. 调研目标

围绕“Windows 桌面端磁盘管理与安全清理”场景，调研当前主流产品的设计模式、能力边界与体验共性，为 CClear 的产品策略和原型开发提供依据。

## 2. 代表产品

### 2.1 WinDirStat

- 核心定位：磁盘占用可视化与清理辅助
- 核心模式：目录树 + Treemap + 扩展名统计三栏联动
- 设计特点：
  - 用一次扫描建立全局空间地图
  - 用颜色区分文件类型
  - 通过“看见大块区域”快速定位空间热点
- 优势：可解释性强，学习成本低
- 局限：扫描速度依赖遍历，现代 UI 感较弱
- 参考来源：
  - https://windirstat.net/
  - https://github.com/WinDirStat/WinDirStat

### 2.2 WizTree

- 核心定位：高速磁盘空间分析
- 核心模式：列表优先 + 大文件排序 + 快速过滤
- 设计特点：
  - 对 NTFS 盘直接读取 MFT，以速度建立竞争优势
  - 先给结果，再深入定位与删除
  - 适合“我只想马上找到最大文件”的任务流
- 优势：扫描极快，适合 C 盘应急处理
- 局限：对文件系统实现依赖较强，跨平台和非 NTFS 能力受限
- 参考来源：
  - https://www.diskanalyzer.com/about

### 2.3 TreeSize Free

- 核心定位：偏企业风格的磁盘分析与管理
- 核心模式：Windows Explorer 风格树视图 + 文件级钻取 + 过滤与报表
- 设计特点：
  - 强调层级浏览、排序、过滤、导出
  - 强调本地数据处理与企业可控性
  - 清理动作与分析动作紧耦合，但更偏审慎管理
- 优势：信息密度高，适合高级用户
- 局限：对普通用户来说略重
- 参考来源：
  - https://www.jam-software.com/treesize_free
  - https://treesize.net/

### 2.4 SpaceSniffer

- 核心定位：交互式空间可视化探索
- 核心模式：Treemap 缩放浏览 + 过滤器驱动
- 设计特点：
  - 鼠标点击与缩放就是核心交互
  - 支持文件名、时间、大小、标签过滤
  - 强调“探索式分析”而不是表单式管理
- 优势：直觉、轻量、便携
- 局限：在复杂任务上，表格筛选和批处理能力不足
- 参考来源：
  - https://www.uderzo.it/main_products/space_sniffer/

### 2.5 Windows Storage Sense

- 核心定位：系统内建自动化清理
- 核心模式：规则化后台清理
- 设计特点：
  - 临时文件、回收站、云文件脱水等场景高度标准化
  - 强调周期性自动执行与低心智负担
  - 适合“持续保养”，不适合深度诊断
- 优势：系统级、风险相对可控
- 局限：可解释性弱，缺少“为什么空间没了”的分析视图
- 参考来源：
  - https://learn.microsoft.com/en-us/windows/configuration/storage/storage-sense

## 3. 设计模式总结

### 3.1 主流模式一：扫描分析模式

- 先扫描，再呈现总体空间结构
- 常见呈现方式：
  - 目录树
  - 大文件列表
  - 文件类型统计
  - Treemap 可视化
- 代表产品：WinDirStat、WizTree、TreeSize、SpaceSniffer

### 3.2 主流模式二：规则清理模式

- 先定义可安全处理的文件集合，再执行清理
- 常见规则：
  - 临时文件
  - 回收站
  - 下载目录旧文件
  - 云文件本地缓存
- 代表产品：Storage Sense、部分系统优化工具

### 3.3 主流模式三：探索式定位模式

- 用户不先做复杂配置，而是通过视觉热点逐层深入
- 核心目标是快速回答“究竟是谁占满了磁盘”
- 代表产品：WinDirStat、SpaceSniffer

### 3.4 主流模式四：专业管理模式

- 通过排序、过滤、导出、计划任务等能力服务高频用户
- 更像“磁盘分析工作台”而不是“一次性清理工具”
- 代表产品：TreeSize

## 4. 用户体验共性

- 都把“发现大文件/大目录”作为第一入口
- 都尽量减少用户手动遍历文件夹的负担
- 都强调“分析先于删除”，降低误删风险
- 清理动作通常需要二次确认
- 真正优秀的产品会把“速度”和“安全”同时做好

## 5. 市场空白与机会

当前主流产品存在两个明显断层：

- 分析很强，但对普通用户不够安全友好
- 自动清理很方便，但对空间来源解释不足

因此 CClear 的产品机会是：

- 为“C 盘爆满但不懂系统结构”的普通用户提供低门槛入口
- 把“分析、搜索、建议、清理”串成一条清晰工作流
- 默认采用安全策略，例如回收站优先、风险分层、系统目录保护
- 重点解决 Windows 个人电脑上的真实高频场景，而不是泛化做成复杂运维平台

## 6. 对 CClear 的启示

### 6.1 需要保留的优秀模式

- WinDirStat 的三视图解释力
- WizTree 的“速度优先”心智
- TreeSize 的筛选与管理能力
- SpaceSniffer 的直觉式探索体验
- Storage Sense 的规则清理思想

### 6.2 需要避免的问题

- 把高级信息直接压给普通用户
- 未分层展示风险，导致用户对删除动作不放心
- 只做“扫描器”而不形成可执行的清理闭环

## 7. 结论

CClear 适合采用“安全清理工作台”定位，而不是仅做另一个空间可视化工具。产品应以“先看清、再筛选、后清理”为主线，在保证分析效率的同时，把高风险系统位置隔离，把可安全处理的空间释放动作做得足够明确、足够可逆。
