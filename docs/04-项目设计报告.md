# CClear 项目设计报告

## 1. 设计目标

构建一个面向 Windows 的桌面端磁盘管理工具原型，以“扫描分析、搜索定位、安全清理”三步闭环帮助用户快速缓解 C 盘空间不足问题。

## 2. 产品定位

- 产品类型：个人电脑磁盘空间管理桌面工具
- 目标场景：C 盘爆满、更新失败、安装失败、空间来源不明确
- 产品主张：先看清，再筛选，后清理；默认安全，可解释，可回退

## 3. 总体架构

### 3.1 分层结构

- 表现层：Tkinter 桌面界面
- 应用层：扫描、搜索、清理工作流编排
- 服务层：文件系统遍历、统计聚合、风险判断
- 系统层：Windows Shell API 与资源管理器联动

### 3.2 模块划分

- `cclear/app.py`
  - 窗口布局
  - 事件绑定
  - 后台任务调度
  - 结果渲染
- `cclear/services.py`
  - 扫描
  - 搜索
  - 清理分析
  - 回收站清理
  - 路径风险判断
- `tests/test_services.py`
  - 核心服务测试

## 4. 功能设计

## 4.1 扫描分析

### 输入

- 用户选择的根目录，默认建议 C 盘

### 处理流程

- 读取目录树
- 统计文件数、目录数、总大小
- 计算最大文件列表
- 计算最大目录列表
- 计算扩展名分布
- 收集跳过项与错误项

### 输出

- 指标卡片
- 最大文件列表
- 最大目录列表
- 扩展名统计表

## 4.2 文件搜索

### 输入

- 根目录
- 搜索关键词
- 最小文件大小

### 处理流程

- 递归遍历
- 关键词匹配
- 大小过滤
- 结果限流

### 输出

- 匹配结果表
- 打开所在位置
- 移入回收站动作

## 4.3 清理中心

### 可安全分析项

- 用户临时目录
- Windows 临时目录
- 下载目录中的大文件建议
- 回收站清空动作入口

### 风险分层

- 低风险：用户临时文件
- 中风险：下载目录旧大文件、Windows 临时目录
- 高风险：系统目录、程序目录、系统组件目录

### 执行原则

- 默认回收站优先
- 高风险路径不提供删除
- 系统级动作二次确认

## 6. 关键流程设计

## 6.1 扫描流程

1. 用户选择目录
2. 界面层发起后台扫描线程
3. 优先检查本地缓存快照是否可复用
4. 若缓存可用则直接返回结果，否则执行实时遍历与聚合
5. 进度通过事件队列回传
6. 扫描完成后写入本地索引缓存
7. 主线程刷新状态和结果列表

## 6.2 搜索流程

1. 用户输入关键词与最小体积
2. 界面层发起后台搜索线程
3. 优先从最近扫描缓存中过滤结果
4. 如缓存不可用或过期，则退回实时遍历
5. 主线程渲染结果表
6. 用户执行定位或移入回收站

## 6.3 清理流程

1. 用户触发清理分析
2. 服务层生成候选项与估算空间
3. 用户确认清理动作
4. 服务层调用回收站接口
5. 主线程展示成功与失败信息

## 7. UI 设计

### 7.1 布局

- 顶部：产品标题、路径选择、状态栏
- 标签页一：扫描概览
- 标签页二：文件搜索
- 标签页三：安全清理

### 7.2 交互原则

- 操作入口尽量少
- 首次打开即可直接扫描 C 盘
- 结果优先展示最大空间占用者
- 所有清理动作都要求用户理解后再执行

## 8. 异常设计

- 权限不足：跳过并记录
- 文件被占用：清理失败并提示
- 根目录不存在：直接报错
- 搜索无结果：显示空结果但不报错
- 回收站接口失败：提示用户稍后重试或以更高权限运行

## 9. 迭代计划

### 9.1 第一阶段

- 完成扫描、搜索、清理的 MVP

### 9.2 第二阶段

- 完成索引缓存与搜索复用
- 增加 Treemap 可视化
- 增加重复文件检测
- 研究增量同步与缓存失效策略

### 9.3 第三阶段

- 增加自动清理策略
- 增加定时任务与历史对比
- 增加更精细的系统目录识别

## 10. 结论

CClear 的设计重点不是“删得多”，而是“删得准、删得安全、删之前看得懂”。因此系统设计坚持风险分层、模块分层与执行分层，先保证用户敢用、会用，再逐步叠加更高阶的自动化能力。
